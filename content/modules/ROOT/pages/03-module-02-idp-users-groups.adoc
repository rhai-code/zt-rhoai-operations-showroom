= Module 2: Integrate with IDP, Users & Group Management
:navtitle: IDP, Users & Group Management

== Learning Objectives

By the end of this module you will be able to:

* Deploy FreeIPA in-cluster as an LDAP directory using Helm
* Configure an LDAP identity provider on OpenShift
* Configure an OIDC identity provider using Keycloak
* Create persona-based groups for data science team members
* Configure the RHOAI Auth CR to restrict dashboard access to authorized groups
* Build and serve a wine quality classifier using Feature Store (Feast)
* Register a trained model in the RHOAI model registry
* Describe the full RBAC surface area across RHOAI subsystems

== Identity Provider Architecture

RHOAI inherits its authentication from OpenShift, which supports multiple identity providers simultaneously. In this module you will configure two complementary providers:

* **LDAP via FreeIPA** -- Provides centralized user and group directory services. Groups defined in FreeIPA map directly to OpenShift groups, enabling persona-based access control.
* **OIDC via Keycloak** -- Provides federated single sign-on with support for multi-factor authentication, social login, and fine-grained authorization flows.

In production environments, these providers connect to existing enterprise directories (Active Directory, Okta, Azure AD). This workshop deploys standalone instances to demonstrate the integration patterns without requiring external infrastructure.

== Exercise 1: Deploy FreeIPA Using Helm

FreeIPA provides LDAP directory services, Kerberos authentication, DNS, and certificate authority functions. You will deploy it as the primary user directory for this workshop.

=== Step 1: Add the Helm Repository

[source,bash,role="execute"]
----
helm repo add freeipa https://freeipa.github.io/helm-charts
helm repo update
----

=== Step 2: Create the FreeIPA Namespace

[source,bash,role="execute"]
----
oc new-project freeipa
----

=== Step 3: Create the FreeIPA Values File

[source,bash,role="execute",subs="attributes"]
----
cat <<EOF > /tmp/freeipa-values.yaml
replicas: 1
image:
  repository: quay.io/freeipa/freeipa-server
  tag: fedora-latest
server:
  realm: EXAMPLE.COM
  domain: example.com
  adminPassword: "{password}"
  dsPassword: "{password}"
persistence:
  enabled: true
  size: 5Gi
service:
  type: ClusterIP
route:
  enabled: true
  host: ipa.{openshift_cluster_ingress_domain}
securityContext:
  runAsUser: 0
  runAsGroup: 0
  fsGroup: 0
EOF
----

=== Step 4: Install FreeIPA

[source,bash,role="execute"]
----
helm upgrade --install freeipa freeipa/freeipa-server \
  -n freeipa \
  -f /tmp/freeipa-values.yaml \
  --timeout 10m \
  --wait
----

[NOTE]
====
FreeIPA initial setup takes 5-8 minutes as it configures the LDAP directory, Kerberos KDC, and internal CA. The `--wait` flag ensures the Helm command does not return until the pod is healthy.
====

== Exercise 2: Configure LDAP Identity Provider on OpenShift

Now configure OpenShift to authenticate users against the FreeIPA LDAP directory.

=== Step 1: Retrieve the FreeIPA CA Certificate

[source,bash,role="execute"]
----
oc exec -n freeipa $FreeIPA_POD -- cat /etc/ipa/ca.crt > /tmp/freeipa-ca.crt
----

=== Step 2: Create the CA ConfigMap

[source,bash,role="execute"]
----
oc create configmap freeipa-ca \
  --from-file=ca.crt=/tmp/freeipa-ca.crt \
  -n openshift-config
----

=== Step 3: Create the Bind Password Secret

[source,bash,role="execute",subs="attributes"]
----
oc create secret generic freeipa-ldap-secret \
  --from-literal=bindPassword="{password}" \
  -n openshift-config
----

=== Step 4: Patch the OAuth Configuration

[source,bash,role="execute"]
----
oc patch oauth cluster --type=merge -p '
{
  "spec": {
    "identityProviders": [
      {
        "name": "freeipa-ldap",
        "type": "LDAP",
        "mappingMethod": "claim",
        "ldap": {
          "attributes": {
            "id": ["dn"],
            "email": ["mail"],
            "name": ["cn"],
            "preferredUsername": ["uid"]
          },
          "bindDN": "uid=admin,cn=users,cn=accounts,dc=example,dc=com",
          "bindPassword": {
            "name": "freeipa-ldap-secret"
          },
          "ca": {
            "name": "freeipa-ca"
          },
          "insecure": false,
          "url": "ldaps://freeipa.freeipa.svc.cluster.local:636/cn=users,cn=accounts,dc=example,dc=com?uid"
        }
      }
    ]
  }
}'
----

=== Step 5: Wait for OAuth Pods to Roll

The OAuth server pods will restart to pick up the new configuration:

[source,bash,role="execute"]
----
oc rollout status deployment/oauth-openshift -n openshift-authentication --timeout=120s
----

=== Step 6: Sync LDAP Groups to OpenShift

Create a sync configuration to pull FreeIPA groups into OpenShift:

[source,bash,role="execute"]
----
cat <<'EOF' > /tmp/ldap-sync.yaml
kind: LDAPSyncConfig
apiVersion: v1
url: ldaps://freeipa.freeipa.svc.cluster.local:636
bindDN: uid=admin,cn=users,cn=accounts,dc=example,dc=com
bindPassword:
  file: /tmp/bind-password
ca: /tmp/freeipa-ca.crt
insecure: false
rfc2307:
  groupsQuery:
    baseDN: cn=groups,cn=accounts,dc=example,dc=com
    scope: sub
    derefAliases: never
    filter: (objectClass=groupOfNames)
  groupUIDAttribute: dn
  groupNameAttributes:
  - cn
  groupMembershipAttributes:
  - member
  usersQuery:
    baseDN: cn=users,cn=accounts,dc=example,dc=com
    scope: sub
    derefAliases: never
  userUIDAttribute: dn
  userNameAttributes:
  - uid
EOF
----

[source,bash,role="execute",subs="attributes"]
----
echo -n "{password}" > /tmp/bind-password
oc adm groups sync --sync-config=/tmp/ldap-sync.yaml --confirm
rm /tmp/bind-password
----

== Exercise 3: Configure OIDC Identity Provider Using Keycloak

Keycloak provides OpenID Connect (OIDC) authentication with support for federated identity, multi-factor authentication, and fine-grained authorization.

=== Step 1: Verify Keycloak Is Running

Your workshop environment includes a pre-deployed Keycloak instance. Verify it is accessible:

[source,bash,role="execute"]
----
oc get pods -n keycloak -l app=keycloak
----

Expected output:

----
NAME                        READY   STATUS    RESTARTS   AGE
keycloak-0                  1/1     Running   0          1h
----

Access the Keycloak admin console at:

{keycloak_url}

=== Step 2: Create an OpenShift Client in Keycloak

[source,bash,role="execute",subs="attributes"]
----
KEYCLOAK_POD=$(oc get pods -n keycloak -l app=keycloak -o jsonpath='{.items[0].metadata.name}')

oc exec -n keycloak $KEYCLOAK_POD -- /opt/keycloak/bin/kcadm.sh config credentials \
  --server http://localhost:8080 \
  --realm master \
  --user admin \
  --password {password}

oc exec -n keycloak $KEYCLOAK_POD -- /opt/keycloak/bin/kcadm.sh create clients \
  -r master \
  -s clientId=openshift \
  -s enabled=true \
  -s 'redirectUris=["https://oauth-openshift.{openshift_cluster_ingress_domain}/oauth2callback/keycloak-oidc"]' \
  -s clientAuthenticatorType=client-secret \
  -s secret=openshift-client-secret \
  -s directAccessGrantsEnabled=true
----

=== Step 3: Create the OIDC Client Secret in OpenShift

[source,bash,role="execute"]
----
oc create secret generic keycloak-oidc-secret \
  --from-literal=clientSecret=openshift-client-secret \
  -n openshift-config
----

=== Step 4: Add the OIDC Identity Provider to OAuth

[source,bash,role="execute",subs="attributes"]
----
oc patch oauth cluster --type=json -p '[
  {
    "op": "add",
    "path": "/spec/identityProviders/-",
    "value": {
      "name": "keycloak-oidc",
      "type": "OpenID",
      "mappingMethod": "claim",
      "openID": {
        "clientID": "openshift",
        "clientSecret": {
          "name": "keycloak-oidc-secret"
        },
        "issuer": "{keycloak_url}/realms/master",
        "claims": {
          "preferredUsername": ["preferred_username"],
          "name": ["name"],
          "email": ["email"]
        }
      }
    }
  }
]'
----

=== Step 5: Wait for OAuth Rollout

[source,bash,role="execute"]
----
oc rollout status deployment/oauth-openshift -n openshift-authentication --timeout=120s
----

=== Step 2: Configure the RHOAI Auth CR

The RHOAI Auth CR (`services.platform.opendatahub.io`) controls which groups can access the RHOAI dashboard. Update it to use the groups you created:

[source,bash,role="execute"]
----
cat <<'EOF' | oc apply -f -
apiVersion: services.platform.opendatahub.io/v1alpha1
kind: Auth
metadata:
  name: auth-config
  namespace: redhat-ods-applications
spec:
  adminGroups:
    - rhods-admins
  allowedGroups:
    - rhods-users
EOF
----

[IMPORTANT]
====
The `adminGroups` list defines who can administer RHOAI settings (manage serving runtimes, cluster settings, accelerator profiles). The `allowedGroups` list defines who can access the RHOAI dashboard at all. Users not in `allowedGroups` will see an "Access denied" page.
====

== Exercise 5: Build and Serve a Wine Quality Classifier Using Feature Store

In this exercise you will use Feast (Feature Store) to prepare features, train a wine quality classification model, and deploy it for inference. This exercise demonstrates how the persona-based groups you configured interact with RHOAI data science workflows.

=== Step 1: Create the Data Science Project

[source,bash,role="execute"]
----
oc new-project wine-classifier
oc adm policy add-role-to-group edit data-scientists -n wine-classifier
----

=== Step 2: Deploy the Feature Store (Feast)

[source,bash,role="execute"]
----
cat <<'EOF' | oc apply -f -
apiVersion: v1
kind: ConfigMap
metadata:
  name: feast-feature-repo
  namespace: wine-classifier
data:
  feature_store.yaml: |
    project: wine_quality
    registry: /tmp/feast-registry/registry.db
    provider: local
    online_store:
      type: sqlite
      path: /tmp/feast-online/online_store.db
    entity_key_serialization_version: 3
  wine_features.py: |
    from feast import Entity, FeatureView, Field, FileSource
    from feast.types import Float64, Int64
    from datetime import timedelta

    wine_sample = Entity(
        name="wine_id",
        join_keys=["wine_id"],
    )

    wine_source = FileSource(
        path="/data/wine-quality.parquet",
        timestamp_field="event_timestamp",
    )

    wine_features = FeatureView(
        name="wine_features",
        entities=[wine_sample],
        ttl=timedelta(days=365),
        schema=[
            Field(name="fixed_acidity", dtype=Float64),
            Field(name="volatile_acidity", dtype=Float64),
            Field(name="citric_acid", dtype=Float64),
            Field(name="residual_sugar", dtype=Float64),
            Field(name="chlorides", dtype=Float64),
            Field(name="free_sulfur_dioxide", dtype=Float64),
            Field(name="total_sulfur_dioxide", dtype=Float64),
            Field(name="density", dtype=Float64),
            Field(name="ph", dtype=Float64),
            Field(name="sulphates", dtype=Float64),
            Field(name="alcohol", dtype=Float64),
            Field(name="quality", dtype=Int64),
        ],
        source=wine_source,
        online=True,
    )
EOF
----

=== Step 3: Create the Training Pipeline Script

[source,bash,role="execute"]
----
cat <<'PYEOF' | oc create configmap wine-training-script -n wine-classifier --from-file=train.py=/dev/stdin
import pandas as pd
import numpy as np
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import classification_report, accuracy_score
import joblib
import os

# Load wine quality dataset
from sklearn.datasets import load_wine
data = load_wine()
df = pd.DataFrame(data.data, columns=data.feature_names)
df['target'] = data.target

print(f"Dataset shape: {df.shape}")
print(f"Classes: {np.unique(df['target'])}")

# Split data
X_train, X_test, y_train, y_test = train_test_split(
    df[data.feature_names], df['target'],
    test_size=0.2, random_state=42
)

# Train model
model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X_train, y_train)

# Evaluate
y_pred = model.predict(X_test)
accuracy = accuracy_score(y_test, y_pred)
print(f"\nAccuracy: {accuracy:.4f}")
print(f"\nClassification Report:\n{classification_report(y_test, y_pred, target_names=data.target_names)}")

# Save model
model_dir = "/mnt/models"
os.makedirs(model_dir, exist_ok=True)
model_path = os.path.join(model_dir, "wine-classifier.joblib")
joblib.dump(model, model_path)
print(f"\nModel saved to {model_path}")
PYEOF
----

=== Step 4: Run the Training Job

[source,bash,role="execute"]
----
cat <<'EOF' | oc apply -f -
apiVersion: batch/v1
kind: Job
metadata:
  name: wine-training
  namespace: wine-classifier
spec:
  template:
    spec:
      containers:
      - name: trainer
        image: registry.redhat.io/ubi9/python-311:latest
        command:
        - bash
        - -c
        - |
          pip install scikit-learn joblib pandas numpy && \
          python /scripts/train.py
        volumeMounts:
        - name: training-script
          mountPath: /scripts
        - name: model-storage
          mountPath: /mnt/models
      volumes:
      - name: training-script
        configMap:
          name: wine-training-script
      - name: model-storage
        persistentVolumeClaim:
          claimName: wine-model-pvc
      restartPolicy: Never
  backoffLimit: 2
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: wine-model-pvc
  namespace: wine-classifier
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
EOF
----

=== Step 5: Wait for Training to Complete

----

== Reference: MLOps RBAC Surface Area

RHOAI RBAC spans multiple subsystems, each with its own authorization model. The following table provides a comprehensive reference for the RBAC surfaces that platform administrators must understand and configure.

[cols="2,2,3,2",options="header"]
|===
|Subsystem |Resource Type |RBAC Mechanism |Key Groups/Roles

|*RHOAI Dashboard*
|Dashboard access, settings
|Auth CR (`adminGroups`, `allowedGroups`)
|`rhods-admins`, `rhods-users`

|*Data Science Projects*
|Namespaces, workbenches, pipelines
|OpenShift RBAC (`RoleBinding` in namespace)
|`admin`, `edit`, `view` ClusterRoles

|*Workbenches (Notebooks)*
|Notebook CR lifecycle
|Custom ClusterRoles with `opendatahub.io/role-type` label
|`workbench-maintainer`, `workbench-reader`, `workbench-operator`, `workbench-editor`

|*Model Serving (KServe)*
|InferenceService, ServingRuntime
|OpenShift RBAC in serving namespace
|`admin`, `edit` for create/update; `view` for read-only

|*Model Serving (ModelMesh)*
|InferenceService, ServingRuntime
|OpenShift RBAC in serving namespace
|Same as KServe; namespace-scoped

|*Model Registry*
|RegisteredModel, ModelVersion, ModelArtifact
|Model Registry RBAC (namespace-scoped)
|Tied to namespace `RoleBinding`; no separate auth model

|*Pipelines (Data Science Pipelines)*
|PipelineRun, Pipeline definitions
|OpenShift RBAC + DSP namespace access
|`admin`/`edit` for pipeline creation; `view` for run monitoring

|*Distributed Workloads (Kueue)*
|ClusterQueue, LocalQueue, Workload
|Kueue RBAC (ClusterRole for queue admin)
|Cluster-scoped for ClusterQueue; namespace-scoped for LocalQueue/Workload

|*TrustyAI*
|TrustyAIService, bias/explainability data
|OpenShift RBAC in TrustyAI namespace
|`admin`/`edit` for configuration; `view` for dashboard access

|*Model Monitoring*
|ModelMonitor, metrics endpoints
|OpenShift RBAC + Prometheus RBAC
|`monitoring-edit` for alert rules; `view` for dashboard access

|*Custom Serving Runtimes*
|ServingRuntime (cluster-scoped)
|Cluster admin or delegated ClusterRole
|Typically restricted to `rhods-admins`; runtime selection available to project `edit` role
|===

[CAUTION]
====
This table covers the primary RBAC surfaces as of RHOAI 3.5. Additional subsystems (guardrails, evaluation hub) are in Technology Preview and may introduce their own authorization models. Always consult the https://docs.redhat.com/en/documentation/red_hat_openshift_ai_self-managed/3.5[RHOAI 3.5 documentation] for the latest RBAC guidance.
====

[WARNING]
====
The `cluster-admin` ClusterRole bypasses all RBAC checks. Avoid granting it to data science users. Instead, use the minimum set of roles described above to implement least-privilege access.
====
